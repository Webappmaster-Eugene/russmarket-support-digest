# MCP для сводки поддержки

Инструмент `compile_support_digest` принимает кейсы из CRM и сообщения из
рабочих чатов, затем возвращает приоритеты, раздельные сведения из каждого
источника, вопросы для сверки и следующие действия. Он использует тот же
модуль правил, что и сайт.

## Запустить пример

Из корня репозитория с Node.js 22 выполните:

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm mcp:demo
```

Команда собирает сервер, подключает к нему MCP-клиент и показывает готовую
сводку по П-08, С-24, С-17 и П-09. Дата понедельника и время сообщений в
учебном примере заданы для воспроизводимости. Сроки и отметка о приёмке
в 09:20 взяты из задания. Для новых кейсов передавайте данные в
`compile_support_digest` через свой MCP-клиент.

## Подключить к клиенту

Выполните `pnpm mcp:build`. В клиенте добавьте локальный сервер типа
`stdio`, запустив файл `.build/support-mcp.mjs` через Node.js 22.
Например, для конфигурации клиента с полем `mcpServers`:

```json
{
  "mcpServers": {
    "support-digest": {
      "command": "node",
      "args": ["/путь/к/russmarket-support-digest/.build/support-mcp.mjs"]
    }
  }
}
```

Замените путь абсолютным. Если клиент запускается с отдельным окружением,
в `command` укажите абсолютный путь к Node.js 22. Сам сервер запускается
локально, обрабатывает переданные данные в памяти и возвращает результат
через стандартный вывод по протоколу MCP. Ключи, PostgreSQL и сетевые
подключения для расчёта не нужны. Рабочую переписку передавайте только
через клиент, одобренный для таких данных.

## Вызов на новых данных

Пример аргументов инструмента для доставки со сроком 12:00 и оценкой
курьера 13:00:

```json
{
  "asOf": "2026-11-23T10:00:00+03:00",
  "cases": [
    {
      "record": {
        "id": "П-101",
        "kind": "delivery",
        "crm": {
          "status": "in_transit",
          "dueAt": "2026-11-23T12:00:00+03:00"
        }
      },
      "chat": [
        {
          "role": "courier",
          "text": "Приеду к 13:00.",
          "at": "2026-11-23T09:50:00+03:00"
        }
      ]
    }
  ]
}
```

Результат — **«Проверить сегодня»**. В CRM срок 12:00, а оценка курьера позже.
Поддержке нужно уточнить дату и время прибытия и согласовать перенос с точкой.
Результат доступен как читаемый текст и как JSON в `structuredContent.digest`.

Поля `record` соответствуют [контракту случаев](api.md). За один вызов можно
передать до 30 случаев и до 10 сообщений по каждому, до 2000 символов в
сообщении. ID должны быть уникальны. Время сводки и сообщений передаётся со
смещением часового пояса. Поле `chat` по умолчанию пустое, а `conflict`
у сообщения по умолчанию равно `false`.

## Правила

| Случай | Как выбирается приоритет |
| --- | --- |
| Оформление | Если документы подтверждены в CRM, оставить для сведения. Иначе сравнить дату первого выхода с датой сводки по Москве. Прошедший день означает «Срочно», текущий — «Проверить сегодня», будущий — «До срока». |
| Увольнение | Если руководитель подтвердил увольнение в CRM, оставить для сведения. Иначе то же правило применяется к последнему рабочему дню. Фраза «руководитель в курсе» сама по себе согласование не подтверждает. |
| Открытая доставка | Срок наступил или прошёл — «Срочно». Если срок ещё впереди, но ожидаемое время курьера позже срока, уже прошло или неясно, — «Проверить сегодня». В остальных случаях — «До срока». |
| Принятая доставка | Если приёмка подтверждена в CRM, оставить для сведения. Если получатель в момент приёмки или позже явно сообщил, что карты не получены, проверить расхождение сегодня. |

Отмеченное и ещё не разобранное расхождение поднимает случай как минимум до
«Проверить сегодня». Срочный случай сохраняет свой приоритет. Сообщения
хранятся отдельно от данных CRM. Сводка использует сообщения к моменту
`asOf` включительно и не перезаписывает статус CRM по переписке.

Время прибытия ищется в последнем сообщении курьера. Например, «Приеду к
13:00» и «Не раньше 13:00» относятся к дате сообщения по Москве. Если
курьер указал несколько вариантов или время неоднозначно, сводка просит
уточнить его. Порядок сводки — от срочных к информационным, а внутри
приоритета сначала идут ближайшие по сроку случаи.

Форма и MCP требуют срок для открытой доставки. Для статуса «Принято»
нужно указать время приёмки к моменту сводки или раньше. Для архивных
записей есть отдельный список на сайте, текущая сводка строится по
активным случаям. При ручном вызове MCP передавайте активные случаи
из той же выгрузки, если нужно сопоставить результаты.
