# API сводки

Все маршруты данных требуют сессию, выданную при входе в браузере. Методы
записи принимают JSON и ожидают заголовок `Origin`, совпадающий с адресом
приложения. Привязка к рабочему пространству берётся из сессии.

| Метод и путь | Действие |
| --- | --- |
| `GET /api/cases` | Список случаев. Параметр `archived=1` выбирает архив. |
| `POST /api/cases` | Создать случай из `id`, `kind` и полей `crm`. Возвращает UUID записи. |
| `GET /api/cases/:id` | Прочитать случай и его переписку по UUID. |
| `PATCH /api/cases/:id` | Применить `action` к указанной `version`. |
| `GET /api/digest` | Текущая сводка для вошедшего пользователя. |
| `GET /api/digests?page=1` | Список сохранённых снимков. |
| `POST /api/digests` | Сохранить текущую сводку. UUID в `id` делает повтор запроса безопасным. |
| `GET /api/digests/:id` | Прочитать снимок. |
| `GET /api/health` | Публичная проверка готовности без рабочих данных. |

`kind` принимает `onboarding`, `offboarding` и `delivery`. Поля CRM для
оформления — `startDate` и `documents` (`awaiting` или `confirmed`).
Для увольнения — `lastDay` и `managerConfirmed`. Для доставки — `status`
(`planned`, `in_transit`, `accepted`), `dueAt` для открытой доставки и
`acceptedAt` для принятой. Указывайте время в ISO 8601 со смещением или `Z`.

Действие `edit` принимает в `value` те же поля, что создание. Для
`message` передайте в `value` поля `role`, `text`, `at` и `conflict`.
Действие `resolve` принимает `messageId` и `resolution`.
`archive` и `restore` используют только `action` и `version`.

Запрос без сессии получает `401`, запись другого пространства — `404`.
Устаревшая версия или повтор ID дают `409`. Неверные поля дают `422` с
указателями в `issues`. Ограничение отдельного JSON-запроса — 16 КиБ.
